What matters for dstack TEE
•  Build for linux/amd64 (add arm64 to avoid manifest issues).
•  Container must listen on port 80 and your gateway URL should include -80 when needed.
•  Use a compose file that:
◦  Mounts /var/run/tappd.sock (TEE adapter socket).
◦  Uses environment mapping (key: value), not list-style env.
•  Provide env via an .env file; the Phala CLI encrypts values into the TEE.
•  Keep CVM names short (≤ 20 chars).

G) Common pitfalls we've avoided
•  "no matching manifest for linux/amd64": always use buildx with linux/amd64 (add arm64 too).
•  Wrong port: set PORT=80 and map 80:80 in compose.
•  Env not applied: always provide --env-file ./.env to the CLI (it encrypts the values for the TEE).
•  Long CVM names: keep ≤ 20 characters.
•  Gateway URL: if the base domain form doesn't respond while booting, use the -80 form.
•  "version obsolete": Remove version field from docker-compose.yml.
•  "failed to read dockerfile": Ensure Dockerfile is in the build context root.
•  "unauthorized environment variable": Some env vars are managed by TEE system, don't include them in .env.
•  CVM stuck in "starting": Check logs via Phala dashboard, may need to restart or redeploy.
